# UC1 : Créer Habitude - Scénario Nominal Très Détaillé

## Informations Générales
- **Identifiant** : UC1
- **Acteur Principal** : Utilisateur authentifié
- **Parties Prenantes** : Système, Base de données
- **Pré-conditions** : 
  - L'Utilisateur est authentifié (UC8)
  - L'Utilisateur a accès à l'interface principale
  - La session est active et valide
- **Post-conditions** :
  - Une nouvelle instance d'Habitude est créée et persistée
  - L'Habitude est associée au profil de l'Utilisateur
  - Les données sont affichées dans la liste des habitudes actives
  - Un message de confirmation est affiché

---

## Scénario Nominal Détaillé

### **Étape 1 : Accès à l'interface de création**

#### Action de l'Utilisateur
1. L'Utilisateur ouvre l'application sur son appareil (web, mobile, ou desktop)
2. L'Utilisateur est automatiquement redirigé vers le tableau de bord principal après authentification
3. L'Utilisateur visualise l'interface avec :
   - Un en-tête contenant le nom de l'application et son profil
   - Une section "Mes habitudes actives" affichant les habitudes existantes (si applicable)
   - Un tableau de bord avec statistiques (streak, taux de réussite, badges)
   - Un bouton proéminent "Créer une nouvelle habitude"
4. L'Utilisateur localise visuellement le bouton de création :
   - Position : Généralement en haut à droite ou au centre
   - Apparence : Bouton primaire en couleur vive (bleu, vert) avec icône "+"
   - Label : "+ Créer une habitude" ou "+ Nouvelle habitude"
5. L'Utilisateur positionne son curseur (desktop) ou son doigt (mobile) sur le bouton
6. L'Utilisateur effectue un clic (desktop) ou un tap (mobile)

#### Réaction du Système
1. **Interception de l'événement**
   - Le Système détecte l'événement `onClick` ou `onTap` sur le bouton
   - Le Système capture le timestamp exact de l'action : `2026-01-27 14:25:10.532`
   - Le Système enregistre l'événement dans les analytics : "User initiated habit creation"

2. **Vérification de la session**
   - Le Système vérifie que le token de session est valide
   - Le Système vérifie que l'Utilisateur a les permissions nécessaires
   - Requête : `SELECT role, permissions FROM users WHERE session_token = 'current_token' AND session_expiry > NOW()`
   - Résultat : Session valide ✓

3. **Préparation de l'interface de création**
   - Le Système charge le composant/page de création d'habitude
   - Le Système initialise l'état du formulaire : tous les champs sont vides
   - Le Système prépare les valeurs par défaut :
     - Catégorie : "Non catégorisé" (ou dernière catégorie utilisée)
     - Fréquence : "Quotidienne" (valeur par défaut recommandée)
     - Rappels : Désactivés
     - Liste de micro-actions : Vide

4. **Chargement des données de référence**
   - Le Système récupère la liste des catégories disponibles :
     ```sql
     SELECT id, nom, couleur, icone 
     FROM categories 
     WHERE user_id = 'user_123' OR est_systeme = true 
     ORDER BY est_systeme DESC, nom ASC
     ```
   - Résultat : 12 catégories (7 système + 5 personnalisées)
   - Le Système charge les templates/suggestions (optionnel) :
     - "Faire du sport"
     - "Lire 20 minutes"
     - "Méditer"
     - "Boire 2L d'eau"
     - etc.

5. **Transition visuelle**
   - Sur web/desktop :
     - Soit ouverture d'une nouvelle page avec transition slide/fade (300ms)
     - Soit ouverture d'une modal overlay sur le tableau de bord actuel
   - Sur mobile :
     - Navigation vers une nouvelle vue avec animation slide-in depuis la droite
     - Mise à jour de la barre de navigation avec bouton "Retour"
   - Durée de transition : 250-350ms pour une expérience fluide

6. **Affichage du formulaire complet**
   - Le Système affiche le formulaire structuré en sections

### **Étape 2 : Affichage du formulaire de création**

#### Interface Complète Affichée

Le Système présente un formulaire organisé en 5 sections principales :

#### **Section 1 : Informations de Base**

**Champ "Nom de l'habitude" (Obligatoire)**
- **Position** : Premier champ, en haut du formulaire
- **Label** : "Nom de votre habitude *" (astérisque rouge pour obligatoire)
- **Type** : Input text, taille large (full width ou 80% width)
- **Placeholder** : "Ex: Faire 30 minutes d'exercice, Lire 20 minutes par jour, Méditer..."
- **Attributs HTML** :
  - `type="text"`
  - `required="true"`
  - `minlength="3"`
  - `maxlength="100"`
  - `autocomplete="off"`
- **Apparence** :
  - Bordure grise neutre (non focalisé)
  - Bordure bleue/verte (au focus)
  - Bordure rouge (en cas d'erreur)
  - Fond blanc ou très légèrement coloré
  - Police: 16px (mobile) ou 14px (desktop) pour éviter l'auto-zoom sur mobile
- **Indicateurs** :
  - Compteur de caractères en bas à droite : "0/100"
  - Icône de validation à droite du champ : ✗ (gris) si vide, ✓ (vert) si valide
- **Aide contextuelle** :
  - Icône (i) ou (?) à côté du label
  - Au survol/clic : Tooltip "Choisissez un nom clair et motivant qui décrit précisément votre objectif"

**Champ "Description" (Optionnel)**
- **Position** : Sous le nom
- **Label** : "Description (optionnel)"
- **Type** : Textarea (zone de texte multiligne)
- **Placeholder** : "Décrivez votre objectif et pourquoi cette habitude est importante pour vous..."
- **Attributs HTML** :
  - `rows="4"`
  - `maxlength="500"`
- **Apparence** :
  - Hauteur : 4 lignes visibles par défaut
  - Redimensionnable verticalement (optionnel)
  - Même style de bordure que le champ nom
- **Indicateurs** :
  - Compteur : "0/500"
  - Pas d'icône de validation (optionnel)
- **Aide** : "Cette description vous aidera à rester motivé et à vous rappeler pourquoi vous avez créé cette habitude"

#### **Section 2 : Catégorisation**

**Menu déroulant "Catégorie"**
- **Position** : Sous la description
- **Label** : "Catégorie"
- **Type** : Select/Dropdown amélioré avec recherche
- **Apparence fermée** :
  - Champ rectangulaire ressemblant à un input
  - Affiche la catégorie sélectionnée avec badge coloré et icône
  - Flèche vers le bas à droite indiquant que c'est un menu déroulant
  - Exemple d'affichage : 🏃 Sport (badge bleu)

**Apparence ouverte (menu déroulé)** :
- Panneau déroulant avec effet drop-shadow
- Barre de recherche en haut : "Rechercher une catégorie..."
- Liste scrollable des catégories :

  **Catégories Système (7 options)** :
  ```
  [Section: Catégories prédéfinies]
  
  ⚕️  Santé              (couleur: vert)      [3 habitudes]
  💼  Productivité      (couleur: orange)    [5 habitudes]
  🏃  Sport             (couleur: bleu)      [2 habitudes]

  🧘  Bien-être         (couleur: rose)      [4 habitudes]
  💰  Finance           (couleur: jaune)     [0 habitude]
  👥  Social            (couleur: cyan)      [1 habitude]
  ```

  **Catégories Utilisateur (5 options)** :
  ```
  [Section: Mes catégories personnalisées]
  
  🎨  Art               (couleur: mauve)     [2 habitudes]
  🍳  Cuisine           (couleur: rouge)     [1 habitude]

  🎸  Musique           (couleur: indigo)    [3 habitudes]

  ```

  **Option supplémentaire** :
  ```
  [Séparateur]

  ```

- Chaque option affiche :
  - Icône/emoji à gauche
  - Nom de la catégorie
  - Badge de couleur (petit carré ou rond coloré)
  - Nombre d'habitudes existantes dans cette catégorie (info contextuelle)
  
- **Interaction** :
  - Survol d'une option : Fond légèrement coloré
  - Sélection d'une option : Checkmark visible, option en surbrillance

**Catégorie par défaut sélectionnée** :
- "Non catégorisé" (neutre, gris) si première habitude
- OU dernière catégorie utilisée si l'utilisateur a déjà créé des habitudes

**Fonctionnalité de recherche** :
- L'Utilisateur peut taper dans la barre de recherche
- Le Système filtre en temps réel les catégories affichées
- Ex: Taper "sp" → Affiche uniquement "Sport"

**Création rapide de catégorie** :
- Si l'Utilisateur clique sur "➕ Créer une nouvelle catégorie"
- Le Système ouvre une mini-modal ou inline form :
  ```

  ```
- Après création, la nouvelle catégorie est automatiquement sélectionnée

### **Étape 3 : Saisie du nom de l'habitude**

#### Action de l'Utilisateur - Séquence détaillée

1. **Focus initial**
   - L'Utilisateur visualise le champ "Nom de l'habitude" (premier champ visible)
   - L'Utilisateur lit le placeholder : "Ex: Faire 30 minutes d'exercice..."
   - L'Utilisateur positionne son curseur dans le champ (clic desktop, tap mobile)

2. **Obtention du focus**
   - Le champ reçoit le focus (événement `onFocus`)
   - Le curseur texte apparaît et clignote dans le champ
   - Sur mobile : Le clavier virtuel s'affiche automatiquement (keyboard type: text)
   
3. **Début de la saisie**
   - L'Utilisateur commence à taper
   - Premier caractère : "F"
   - Deuxième caractère : "a"
   - Troisième caractère : "i"
   - etc.

4. **Saisie complète**
   - L'Utilisateur tape lettre par lettre : "Faire 30 minutes de sport"
   - Vitesse de frappe : Variable (rapide, normale, lente)
   - Possibles corrections : 
     - Backspace pour effacer une erreur
     - Sélection de texte pour remplacer
     - Copier-coller (détecté par le système)

#### Réaction du Système - Validation en temps réel

**Pour chaque caractère tapé** :

1. **Capture de l'événement**
   ```javascript
   onInput(event) {
     const value = event.target.value;
     // value = "F", puis "Fa", puis "Fai", etc.
   }
   ```

2. **Mise à jour du compteur de caractères**
   - Après "F" : Compteur affiche "1/100"
   - Après "Fa" : Compteur affiche "2/100"
   - Après "Faire" : Compteur affiche "5/100"
   - ...
   - Après "Faire 30 minutes de sport" : Compteur affiche "26/100"
   
   **Affichage du compteur** :
   - Position : En bas à droite du champ
   - Couleur : 
     - Gris si < 3 caractères (pas encore valide)
     - Vert si 3-90 caractères (valide, dans la zone sûre)
     - Orange si 90-95 caractères (approche de la limite)
     - Rouge si 95-100 caractères (proche du maximum)
     - Rouge clignotant si = 100 caractères (limite atteinte)

3. **Validation de la longueur minimum (3 caractères)**
   
   **État 1 : < 3 caractères (invalide)**
   - Exemple : "F" (1 car.), "Fa" (2 car.)
   - Indicateur de validation : ✗ (gris ou rouge)
   - Bordure du champ : Neutre (grise)
   - Message d'aide : "Minimum 3 caractères requis" (affiché sous le champ en petits caractères gris)
   - Bouton "Enregistrer" : Désactivé (grisé)
   
   **État 2 : >= 3 caractères (valide)**
   - Exemple : "Faire" (5 car.), "Faire 30 minutes de sport" (26 car.)
   - Indicateur de validation : ✓ (vert)
   - Bordure du champ : Verte (subtile)
   - Message d'aide : Disparaît ou remplacé par "✓ Valide"
   - Bouton "Enregistrer" : Activé (si tous les autres champs obligatoires sont aussi valides)

4. **Validation des caractères**
   - Le Système vérifie chaque caractère tapé
   - **Caractères autorisés** :
     - Lettres (a-z, A-Z, avec accents é, è, ê, à, etc.)
     - Chiffres (0-9)
     - Ponctuation de base (. , ! ? - ' ")
     - Espaces
     - Emojis (optionnel, selon configuration)
   
   - **Caractères non autorisés** (si configuré) :
     - Caractères spéciaux : <, >, {, }, [, ], \, |, etc.
     - Tentative d'injection SQL : ' OR '1'='1
     - Scripts : <script>, etc.
   
   - **Si caractère non autorisé détecté** :
     - Option A : Le Système bloque la saisie (caractère n'apparaît pas)
     - Option B : Le Système filtre automatiquement (caractère supprimé)
     - Option C : Le Système affiche un message d'erreur : "Caractère non autorisé : <"
     - Bordure devient rouge temporairement
     - Feedback visuel : Vibration légère (mobile) ou animation shake

5. **Protection contre les attaques**
   - **Détection d'injection SQL** :
     - Si pattern suspect détecté : `' OR 1=1 --`
     - Le Système nettoie automatiquement (sanitization)
     - Ou affiche un avertissement : "Caractères non autorisés détectés"
   
   - **Détection de XSS** :
     - Si balises HTML détectées : `<script>alert('XSS')</script>`
     - Le Système encode automatiquement les entités HTML
     - `<` devient `&lt;`, `>` devient `&gt;`
   
   - **Protection contre le spam** :
     - Si saisie anormalement rapide (robot) : Captcha ou délai forcé
     - Si répétition excessive d'un caractère : "aaaaaaaaaa..." → Avertissement

6. **Feedback visuel progressif**

7. **Validation en temps réel - Résumé**
   Après chaque frappe, le Système :
   - ✓ Compte les caractères
   - ✓ Met à jour le compteur

   - ✓ Vérifie les caractères autorisés

   - ✓ Met à jour l'état du bouton "Enregistrer"
   - ✓ Affiche/cache les messages d'aide
   - ✓ Applique le styling approprié

8. **Perte de focus**
   - L'Utilisateur clique en dehors du champ ou appuie sur Tab
   - Événement `onBlur` déclenché
   - Le Système effectue une validation finale :
     - Si invalide : Message d'erreur devient plus visible (rouge, en gras)
     - Si valide : Indicateur ✓ reste visible, bordure verte disparaît (retour à neutre)
   - Sur mobile : Le clavier se ferme automatiquement
